# 试验基础信息管理审核流程测试文档

## 一、功能概述

实现试验基础信息从草稿到审核的完整流程管理,包括:
- 试验信息的创建、编辑、提交、审核、退回、归档、作废
- 基于状态的操作按钮显示
- 完整的审核记录追踪

## 二、状态说明

| 状态码 | 状态名称 | 说明 |
|--------|---------|------|
| S0 | 草稿 | 新创建的试验,默认状态 |
| S1 | 待审批 | 已提交等待审核 |
| S2 | 已审批 | 审核通过 |
| S3 | 已退回 | 审核未通过,退回修改 |
| S9 | 已归档 | 已归档保存 |
| S10 | 作废 | 已作废 |

## 三、状态流转规则

```
S0(草稿) ──提交审核──> S1(待审批) ──审核通过──> S2(已审批) ──归档──> S9(已归档)
   │                        │
   │                        └──审核退回──> S3(已退回) ──重新提交──> S1(待审批)
   │                                            │
   └──作废──> S10(作废) <──────作废──────────────┘
```

## 四、操作权限说明

### 试验基础信息管理页面(试验创建者/所有者视角)

| 状态 | 可见操作按钮 | 说明 |
|------|------------|------|
| S0(草稿) | 编辑、提交、作废 | 可以编辑草稿、提交审核或作废 |
| S1(待审批) | 查看 | 只能查看,等待审核人处理 |
| S2(已审批) | 查看、归档 | 可以查看或归档 |
| S3(已退回) | 编辑、提交、作废 | 可以修改后重新提交或作废 |
| S9(已归档) | 查看 | 只能查看 |
| S10(作废) | 查看 | 只能查看 |

### 试验基础信息管理审核页面(审核人视角)

#### 待审核标签页(S1)
- 显示所有状态为S1(待审批)的审核记录
- 操作按钮: **审核**

#### 已审核标签页(S2, S3)
- 显示所有已审核(通过S2或退回S3)的审核记录
- 操作按钮: **查看**

## 五、测试步骤

### 测试用例1: 新增试验并完成审核流程

#### 步骤1: 创建草稿试验
1. 进入 **试验基础信息管理** 页面
2. 点击 **新增** 按钮
3. 填写试验基本信息:
   - 选择育种批次
   - 填写试验名称
   - 选择研究中心
   - 选择年份和季节
   - 选择试验设计类型
   - 设置重复次数
4. 点击 **保存** 按钮
5. **预期结果**:
   - 保存成功
   - 返回列表页
   - 新试验状态显示为 `S0(草稿)`
   - 操作列显示: `编辑`、`提交`、`作废` 按钮

#### 步骤2: 编辑草稿
1. 在列表中找到刚创建的试验
2. 点击 **编辑** 按钮
3. 修改试验信息
4. 点击 **保存** 按钮保存草稿
5. **预期结果**:
   - 修改成功
   - 状态仍为 `S0(草稿)`

#### 步骤3: 提交审核
1. 在列表中找到草稿试验
2. 点击 **提交** 按钮
3. 确认提交
4. **预期结果**:
   - 提交成功提示
   - 试验状态变为 `S1(待审批)`
   - 操作列只显示: `查看` 按钮
   - 该试验出现在 **试验基础信息管理审核** 页面的 **待审核** 标签页中

#### 步骤4: 审核人审核(情况A: 审核通过)
1. 进入 **试验基础信息管理审核** 页面
2. 在 **待审核** 标签页找到刚提交的审核记录
3. 点击 **审核** 按钮
4. 查看试验详情
5. 填写审核意见(选填)
6. 点击 **通过** 按钮
7. **预期结果**:
   - 审核成功提示
   - 审核记录状态变为 `S2(已审批)`
   - 审核记录移到 **已审核** 标签页
   - 在 **试验基础信息管理** 页面,试验状态变为 `S2(已审批)`
   - 操作列显示: `查看`、`归档` 按钮

#### 步骤5: 归档试验
1. 返回 **试验基础信息管理** 页面
2. 找到已审批的试验
3. 点击 **归档** 按钮
4. 确认归档
5. **预期结果**:
   - 归档成功提示
   - 试验状态变为 `S9(已归档)`
   - 操作列只显示: `查看` 按钮

### 测试用例2: 审核退回并重新提交流程

#### 步骤1-3: 同测试用例1,创建并提交试验

#### 步骤4: 审核人审核(情况B: 审核退回)
1. 进入 **试验基础信息管理审核** 页面
2. 在 **待审核** 标签页找到审核记录
3. 点击 **审核** 按钮
4. 查看试验详情
5. 填写退回原因(必填)
6. 点击 **退回** 按钮
7. **预期结果**:
   - 退回成功提示
   - 审核记录状态变为 `S3(已退回)`
   - 审核记录移到 **已审核** 标签页
   - 在 **试验基础信息管理** 页面,试验状态变为 `S3(已退回)`
   - 操作列显示: `编辑`、`提交`、`作废` 按钮

#### 步骤5: 修改并重新提交
1. 返回 **试验基础信息管理** 页面
2. 找到已退回的试验
3. 点击 **编辑** 按钮
4. 根据退回原因修改试验信息
5. 点击 **保存** 按钮或 **提交** 按钮
6. **预期结果**:
   - 如点击保存: 状态仍为 `S3(已退回)`
   - 如点击提交: 状态变为 `S1(待审批)`,重新进入审核流程

#### 步骤6: 重新审核通过
- 重复测试用例1的步骤4-5

### 测试用例3: 作废流程

#### 情况A: 作废草稿(S0)
1. 创建草稿试验
2. 点击 **作废** 按钮
3. 填写作废原因
4. 确认作废
5. **预期结果**:
   - 作废成功提示
   - 试验状态变为 `S10(作废)`
   - 操作列只显示: `查看` 按钮

#### 情况B: 作废已退回试验(S3)
1. 找到已退回的试验
2. 点击 **作废** 按钮
3. 填写作废原因
4. 确认作废
5. **预期结果**: 同上

## 六、表单页面按钮说明

### 新增页面
- **取消**: 返回列表页
- **保存**: 保存为草稿(状态S0)
- **提交**: 保存并提交审核(状态变为S1)

### 编辑页面

#### 当试验状态为 S0(草稿) 或 S3(已退回)
- **取消**: 返回列表页
- **保存**: 保存草稿,状态不变
- **提交**: 保存并提交审核(状态变为S1)

#### 当试验状态为 S1(待审批)、S2(已审批)、S9(已归档)、S10(作废)
- 只读模式,无法编辑
- 或不显示编辑按钮

## 七、数据库表结构

### 1. trial_basic(试验基础信息表)
新增字段:
- `trial_status`: 试验状态(S0-S10)
- `created_by/created_name`: 创建人ID/姓名
- `modified_by/modified_name`: 修改人ID/姓名
- `approved_by/approved_name/approved_time`: 审批人信息
- `submitted_by/submitted_name/submitted_time`: 提交人信息
- `rejected_by/rejected_name/rejected_time`: 退回人信息
- `archived_by/archived_name/archived_time`: 归档人信息
- `cancelled_by/cancelled_name/cancelled_time/cancel_reason`: 作废人信息及原因

### 2. trial_basic_audit(审核记录表)
主要字段:
- `audit_id`: 审核记录ID
- `trial_id`: 关联的试验ID
- `audit_status`: 审核状态(S1/S2/S3)
- `audit_opinion`: 审核意见
- `reject_reason`: 退回原因
- `auditor_id/auditor_name/audit_time`: 审核人信息
- `submitter_id/submitter_name/submit_time`: 提交人信息
- `trial_data_snapshot`: 试验数据快照(JSON)

### 3. trial_basic_audit_history(审核历史表)
记录所有操作历史,用于追溯

## 八、API接口

### 试验基础信息管理
- `POST /breeding/trial/submit/{trialId}` - 提交审核
- `POST /breeding/trial/cancel/{trialId}` - 作废试验
- `POST /breeding/trial/archive/{trialId}` - 归档试验

### 审核管理
- `POST /breeding/trial/audit/list` - 分页查询审核列表
- `GET /breeding/trial/audit/getById/{id}` - 根据ID获取审核详情
- `GET /breeding/trial/audit/getByTrialId/{trialId}` - 根据试验ID获取审核详情
- `POST /breeding/trial/audit/perform` - 执行审核(通过/退回)
- `GET /breeding/trial/audit/history/{trialId}` - 查询审核历史

## 九、注意事项

1. **权限控制**: 确保只有有权限的用户才能进行审核操作
2. **数据一致性**: 试验状态和审核记录状态应保持同步
3. **历史追溯**: 所有状态变更都应记录到审核历史表
4. **数据快照**: 每次提交审核时应保存试验数据快照
5. **退回原因**: 退回时必须填写原因
6. **作废原因**: 作废时必须填写原因
7. **并发控制**: 注意处理同一试验的并发操作
